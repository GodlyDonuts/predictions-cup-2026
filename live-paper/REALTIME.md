# Realtime market capture

The single collector supports the official API v1 tournament-wide private broadcast feed. One `tournament:{tournamentId}:markets` channel covers the frozen discovered universe, currently 237 markets. Each `markets_batch` entry is normalized into a scoped per-market batch in a separate restricted session journal. The legacy four-market mode remains available. Codex contest writes remain disabled under the current Daenerys execution handoff.

Install the pinned root dependency with `pnpm install --frozen-lockfile`. The normal collector launcher remains `Start-Paper.ps1`. Runtime `realtime-capture.json` containing `{"schemaVersion":2,"enabled":true,"mode":"market_capture_only","channelMode":"tournament"}` selects the whole frozen universe on the next collector start. Schema version 1 preserves the original four-market scope. Never subscribe to the tournament topic and its per-market topics together. This file belongs under the restricted paper runtime, never the repository.

`realtime-client.mjs` obtains the documented three-hour ephemeral connection token through the same account dispatcher as every other request, only when that budget permits it. The current shared budget v3 prohibits all POSTs, including `POST /realtime/token`. The host reports `blocked_shared_read_only_budget` and performs zero authentication attempts in that state. A separate coordinated token allocation would be required to connect; this implementation does not grant one. The token and SDK objects remain private in memory, with no user/account channel. Authentication refresh and subscription recovery require a fresh REST snapshot. Socket retries are paced to one minute. A refused join is removed immediately and blocks further joins until explicit fresh authentication; it never enters the SDK's rapid rejoin loop.

`realtime-host.mjs` allows at most one depth-200 REST recovery per collector cycle, after the regular account/book work. Both the token request and recovery reads retain the shared serialized admission, persistent rate backoff, and final STOP checks. `REALTIME_STOP` stops the feed alone; the existing collector/global STOP files also apply. Recovery does not bypass the existing REST budget or submit an order.

Every market retains independent revision, book version, receipt clock and connection epoch. A busy second may span multiple envelopes. Invalid inner batches invalidate only their market; ambiguous outer envelopes invalidate the scope. Unknown markets are ignored and cannot expand the frozen allowlist. Mandatory initial snapshots are per market: receiving a full pushed book does not establish initial REST readiness. Periodic REST validation remains mandatory even when fresh frames keep arriving; overdue markets become unavailable until their turn in the bounded recovery queue. The current read share cannot reconcile all 237 markets every two minutes. Capturing broad observations is distinct from having all markets ready for decisions.

`realtime-books.mjs` validates tournament/exchange identity, full versioned books, integer depth, tick prices, local receipt order and bounded source-clock skew. It distinguishes topic revisions from engine book versions. Revision gaps, compact batches, unsequenced trades, socket errors, expiry and staleness block readiness until recovery. A repeated topic revision can still carry a newer book. A duplicate book cannot extend freshness. A known pushed expiry survives an equal-version REST snapshot that omits expiry information. Settlement remains blocked pending authoritative market-state work.

The local `/api/realtime` route and `realtime-stats.json` expose sanitized connection and recovery health. `realtime-session.json` identifies the current exclusive capture file. Session journals contain normalized market fields and recovery/invalidation chronology; they do not contain connection credentials or raw account payloads. Each collector restart creates a new file and preserves prior sessions.

This feed is best effort. Successful REST recovery establishes book state, not a complete historical trade tape. Any later paper experiment must preserve local receipt chronology, subscription epochs, gaps and invalidations. Quote touches or price crossings alone are not fill evidence. Frozen historical paper cohorts keep their original journals, parameters and source identities.

The existing feed collector gains a `PERIODIC` invalidation reason. Existing frozen paper banks continue to load their exact archived source graphs, journals and parameters.

## Passive opportunity observer

`Start-Passive.ps1 -Initialize` freezes a new measurement cohort against the current realtime capture session, source prefix, code identities and future cutoff. It refuses to overwrite an existing bank or journal. Run the launcher without `-Initialize` to replay and resume the same cohort. `PASSIVE_STOP` stops this observer alone. A different realtime session ends the observer; preserve its artifacts before starting a separately named successor.

The observer makes no API calls and no orders. It proposes two distinct hypothetical prices one tick inside a sufficiently wide spread, waits for a later independent nonmarketable activation observation, then records strictly later trade-through evidence. It preserves the highest observed same-or-better queue quantity and does not consume that queue using cancellations or observed trades. Neither a touched quote nor a trade-through is labeled a verified fill. Fixed later price observations measure adverse selection, with missed observations and broken continuity explicitly censored. P&L and simulated-fill fields remain null.

`passive-stats.json` and `/api/passive` publish measurements separately from official trades and existing paper wallets. The observer's own fsynced hash-chain journal supports exact replay; a changed source prefix, processed capture row, code identity or incomplete journal fails closed. Connection success alone is not market-stream evidence: `/api/realtime` distinguishes successful subscriptions from receipt of the first market frame.

## Silent stream recovery

When subscriptions and heartbeats succeed but no market frame has arrived, repeated stale-book recovery is limited to once per market per 120 seconds after a successful recovery. Stale books stay unavailable. Initial joins, a changed connection epoch, explicit gap/error recovery and the first received market frame bypass this quiet-only deferral; the host still performs at most one recovery per service call through the existing serialized dispatcher. The interval is within the official one-to-two-minute periodic resync guidance, checked against the current October 2 changelog and OpenAPI contract.

At 2026-10-03 00:44 UTC, the official sign-up page's loaded browser UI displayed a realtime-paused performance notice. Our socket had successful subscriptions/heartbeats and no wildcard/named broadcast callbacks or parser rejections. This supports continuing REST collection while waiting for restored broadcasts; socket health is not proof of a working trade feed. No passive-fill or fast-order-flow claim follows from REST snapshots. `silentRecoveryIntervalMs` and `quietRecoveryDeferrals` expose the policy without exposing credentials.
