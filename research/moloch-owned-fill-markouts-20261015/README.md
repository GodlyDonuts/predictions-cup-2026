# Owned-fill depth markouts — October 15

This is a streaming offline diagnostic for [Moloch execution task #120](https://github.com/GodlyDonuts/predictions-cup-2026/issues/120). It reads the exact native bank journal and a matching frozen native report. It does not access the API, fit a strategy, alter production, infer account fills from public prints, or establish profitability. The parent execution owner obtains and runs the private inputs. All raw data stays private.

```sh
python3 research/moloch-owned-fill-markouts-20261015/analyze.py \
  --journal /private/frozen-bank/events.ndjson \
  --report /private/frozen-bank/report.json \
  --max-book-age-ms 5000 \
  --post-window-ms 1000 \
  --output /private/diagnostics/public-owned-fill-markouts.json
python3 -m unittest discover -s research/moloch-owned-fill-markouts-20261015 -v
```

The freshness and post-target window values above are **example diagnostic bounds**, not asserted runtime policy. Both must be explicit positive integers. Report them with any result and compare coverage before interpreting marks. Longer windows change the measurement time and must not be described as exact one-second marks. The horizons are 1, 5, 30 and 60 seconds after each fill's actual execution clock. No inventory-age or order-lifetime parameter is inferred.

The snapshot schema is `{sequence, previous, report, orders, fills, hash, ...}` from native `Session`. Pass the **original compact LF-terminated report.json bytes**, retaining its seal; do not pretty-print or reconstruct it. The CLI verifies the report's exact raw-body seal. The journal starts at sequence 1 and contains one compact native row per LF-terminated line: `{event,hash,previous,sequence}` in that exact top-level order. Relevant events are:

- `actual_fill`: `source: official_sig_api_v1`, `orderId`, `actualOrderId`, `fillId`, scope/side/action, actual `quantity`/`price`/`fee`, `executedAt`, `receivedAt`, `processedAt`, `receiptHash`.
- `book`: outer `receivedAt` / optional `processedAt`; `book` contains exchange/market/tournament, `sourceAt`, `requestStartedAt`, `receivedAt`, normalized YES `bids` / `asks` arrays of exact prices and integer quantities. Native normalized REST books can omit `transport`; live-stream books use `official_sig_realtime`. Recorded `sourceRef` is required for priced book provenance. Archived raw source files are not independently retrieved.
- `gap`: exchange and clocks, invalidating the preceding observed book until a new book arrives.

Every snapshot fill must match an actual journal event and its order record. IDs, quantities, prices, exact execution clocks, side/action, first observation and receipt hash must match. Per-order filled totals must agree. Repeated actual-fill events with identical economics are counted as duplicate observations, not additional fills; changed duplicates reject. Public trade events never supply an owned fill or an aggressor label. Fees must be explicitly zero in every actual fill and in the report; nonzero fees reject this version rather than silently assuming a fee model. Integer millionths provide exact depth value and markout sums; rounded decimal means are diagnostics only.

There are three distinct clocks:

1. **Observer decision clock:** the order record's `createdAt` millisecond lower bound. A book needs to have been processed by that bound. The native record cannot prove the exact submillisecond order-decision clock, so a same-event book processed later within that millisecond may be conservatively excluded.
2. **Fill execution clock:** actual official `executedAt`, regardless of when the fill was discovered. A pre-execution book must have been received **and processed** by execution, with source/request/receipt clocks fresh at that time. A book whose old source time predates execution but whose receipt/processing came afterward never gets pre-fill credit. Equal-clock books occurring after the recorded fill also get no pre-fill credit.
3. **Fill observation clock:** the first actual-fill `processedAt` matching report `fill.at`. Delayed observations do not move the execution-based horizon. A retrospective post-horizon book may have arrived before the fill was discovered; that count is explicit and does not imply the bot knew the fill then.

For each clock, the latest causally eligible preceding book is selected, including gap/invalid/stale states. The tool does not search backward for a more favorable older book. A book must have source/request/receipt clocks no later than availability and all ages bounded by `maxBookAgeMs`. Prices must be on tick, levels sorted, bid below ask, and full relevant quantity available. Both sides need full quantity for the quoted-gap diagnostic.

For each post-execution horizon, select the **first recorded book** whose source time lies in `[execution + horizon, execution + horizon + postWindow]`. That first observation is retained even if its freshness or depth fails; a later favorable/full book cannot replace it. Selection is by bank observation order, preserving actual information arrival. The output distinguishes priced observations, stale/invalid states, insufficient full-quantity depth, no book in a completed window, and right censoring before the horizon or inside its still-open window. Zero sum with zero covered shares is no measurement, not a flat investment return. All quantity denominators and missing counts are exposed.

For YES, a hypothetical liquidation SELL walks YES bids; replacement BUY walks YES asks. For NO, liquidation SELL walks `1 - YES ask` and replacement BUY walks `1 - YES bid`, preserving level quantities. A BUY markout is full-depth future liquidation value minus actual fill principal; a SELL markout is actual proceeds minus full-depth future replacement cost. These are hypothetical conditional values, **not actual realized trades**. One observed book may value multiple hypothetical fills; the hypothetical quantities are not jointly executable, and the four horizons must never be added as four earned trades. Own resting liquidity and intervening demand are not removed.

The pre-decision **quoted opposite-side gap** is displayed opposite-side full-depth value minus quoted principal for a BUY, or quoted proceeds minus displayed bid value for a SELL. It is an opportunity-shaped displayed gap, not expected earned spread. The report compares this with actual fill-conditioned future marks and separates changes from a same-quantity pre-execution close value. This can diagnose mechanical spread cost versus subsequent adverse movement. Price relation to the prior observed book is descriptive and cannot identify maker/taker status, actual aggressor or the counterfactual fill probability of a different quote. Results are grouped by actual BUY/SELL and YES/NO, plus public market IDs. Owned-fill-only selection cannot establish unconditional strategy alpha.

The reader consumes exactly the snapshot's sequence prefix using bounded `readline` (16MiB maximum row), without loading the whole journal or reading a live suffix. It verifies contiguous sequence, previous-hash links, per-row **raw native body SHA256**, and exact snapshot head/last clock; it emits exact prefix byte count/SHA256 plus exact input report SHA256. The CLI also verifies the report's raw-body seal; direct Python callers must independently establish that fact or leave `snapshot_seal_verified=False`. A separate `head.json` is not an input: the verified journal head is matched to the supplied report's `previous` value. The raw-body verifier tokenizes top-level fields and removes only the top-level hash value while preserving every original event/number/string lexeme. It never re-encodes negative zero, exponents or Unicode. Tests cover nested hash keys, exponent spelling, negative zero, escapes and Unicode, including tampering rejection. This proves byte-hash linkage to the supplied report head; it does **not** prove native serde canonical reserialization equivalence for arbitrary malicious JSON, authenticate a manifest/seed, retrieve raw receipt files, replay the financial engine, or establish fresh account state. Those flags remain false; no native helper was run. A matching native replay/verifier can provide separate authoritative replay evidence when the execution owner runs it.

Output contains aggregates, public exchange/market IDs and hashes only. It excludes raw order/fill IDs, profile data, raw clocks, source paths and receipt hashes. The CLI refuses output paths equal to either input. Source snapshots should remain private even when the aggregate result is published. Tests use synthetic fixtures only, including exact YES/NO depth economics, late books, stale clocks, gaps, shallow-first selection, censoring, duplicate official observations, ignored public trades, quantity weighting, strict prefix reading, tamper rejection and output redaction.
