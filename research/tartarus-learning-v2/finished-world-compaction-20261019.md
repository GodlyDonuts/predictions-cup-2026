# Remove completed worlds from the next compute chunk

An observed phase014 training tail had seven completed worlds and one continuing world. Existing batches still encoded all eight worlds and passed their terminal padding through the recurrent optimizer. Those extra tensor operations add no economic evidence.

`compact_finished_worlds=true` now gathers the live worlds at the beginning of each compute chunk. Original world IDs, wallets, ledgers, clocks, decisions, action counters and final reports remain on the parent stream. A chunk keeps fixed membership; a world completing inside it keeps terminal padding only until the next chunk. Both inference memory and an accepted optimizer's recomputed memory write back to the original continuing world IDs. Out-of-place write-back preserves older frame tensors. No simulated decision limit, API admission, information delivery or legal action changes.

Stochastic sample coupling across worlds may differ when tensor batch shapes differ; the conditional policy distribution is unchanged. Deterministic checks compare the same decisions and continuing memory, including noncontiguous IDs and staggered endings. Other checks verify accepted PPO write-back, immutable chunk initial memory, final results, counters and explicit Boolean configuration. The focused suite passes163 checks.
