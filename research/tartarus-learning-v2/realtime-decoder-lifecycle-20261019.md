# Realtime lifecycle hints and independent book versions

The original cached SIG OpenAPI SHA256 is `fbdf23e54d317392f9fb4a659b9511a01fad065e7a384f28091ef04894a732c9`. Its Realtime description defines a market settlement item as `{marketId,tournamentId,settledWith,at}`. It explicitly describes the stamped outcome label or `REFUND` as an invalidation hint requiring an authoritative market-state refetch. It does not supply a per-share settlement payout.

The history decoder previously required `exchangeId`, which would fail on the documented market-level signal. It now accepts both batched `marketSettled` items and standalone `market_settled` events, validates tournament/market/source time, preserves the opaque label and original receipt time, and invalidates all known books of that market. It creates no cash, payout, refund or inferred winning-contract direction. A later correction remains a new hint. Actual settlement cash, inventory closure, eligibility and refund semantics still require the missing authoritative lifecycle adapter.

The docs also distinguish delivery revisions from each exchange's book `asOf`. A duplicate delivery can carry a newer book, so the decoder now processes book versions even when it suppresses duplicate trades/invalidation events. Same-version conflicting facts fail; unchanged valid books do not renew snapshot confidence. After a recorded reset or resync gap, an actual full snapshot can restore an invalidated baseline even when its version is unchanged. Older books cannot replace newer ones.
