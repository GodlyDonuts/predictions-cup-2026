# Carry the selected population into the faster trainer

Population037 is a two-island run with one GPU compute coordinator and eight independent source worlds per island. The old continuation helper could target only the single-experiment command. It could not carry this asynchronous population into the already checked founder-retention and64-transition batch settings.

`moloch.learning_actions.island_generation_handoff` now waits until every island has at least one complete generation, then selects each island's latest completed generation. The islands need not have the same cycle number. It retains the actual selected global members, evolved learning rates, entropy coefficients, historical champions, offspring and later cross-island migrations. The original generation journal prefix, checkpoint bytes, experiment identity, global membership, actor calibration, source and dataset are checked. Final generations correctly require no offspring replacement; earlier generations still require their completed replacements.

Only after the selected population is saved can the helper stop the exact simulated trainer through its retained Windows process handle. The original run and every remaining checkpoint are retained, including later partial snapshots. It does not claim to resume incomplete financial worlds. The replacement uses a checked private source snapshot, fresh simulation worlds and fresh fitness. One-time founder mutations are not reapplied. Old scores are not imported, no independent test runs, and no exchange client or production financial control is involved.

The replacement enables `evaluate_founders_before_training: true` and `training_chunk_transitions: 64`. The former prevents first-pass training from displacing a stronger founder. The latter keeps useful PPO batch size as worlds finish: eight/eight, four/sixteen, two/thirty-two and one/sixty-four world/step combinations target64 transitions without capping decisions or changing time, available API actions, wallets or the human reward. Its source also includes the equivalent vectorized historical-record validator. The optimizer schedule changes explicitly; identical learning trajectories or ROI gains are not claimed.

Eleven focused continuation/founder/batch checks pass, plus the eleven-check existing population-handoff suite. The new fixture runs real two-island CPU training through two complete generations, verifies selected checkpoint and hyperparameter identity, handles unequal completed cycles, preserves recorded migration ordering, and rejects unfinished populations, changed membership/checkpoints, cancellation and unexpected process loss. An actual Windows child fixture verifies the exact asynchronous module/run/creation identity before termination. These checks establish continuation behavior, not GPU peak-memory admission, whole-run speed or profitability.

At preparation, active037 and the separate2,768-update CPU development evaluation remain running. The new source must be published, frozen and attached to the exact current process before the one-shot continuation can be queued. The rollout record will distinguish waiting, launched founder evaluation, and actual new learning. ProtectedOctober21–25 remains unconsumed.
