# Recorded public trades reach actor flow through the derived stream

The current API adapter records public prints in server-side trade history, but previously exposed them to actor flow only after paid REST requests. The cached official October19OpenAPI `/realtime/token` description includes public trades in authorized market batches (canonical SHA256fbdf23e54d317392f9fb4a659b9511a01fad065e7a384f28091ef04894a732c9). This missing information path is now an explicit `derived_public_trade_stream=true` profile. It requires the existing derived-stream mode; the default remains false.

Only original compiled SIG trade facts arriving while the simulated token/connection is active are forwarded, at their recorded `available_at_ms`. Executions do not become observations at the earlier execution clock. Token minting retains its charged write. Connected public receipts add no REST admission, no book snapshot and no account reconciliation. Connecting does not replay server history; missed history still needs paid REST recovery.

Receipts update the existing observed-flow features, increment observation revision and can interrupt WAIT. Policy architecture, legal actions and feature dimensions remain unchanged. The policy can still disconnect the stream. New prints are partial observations and do not certify complete tape volume, engine matching provenance or book continuity. In particular, receiving a print does not satisfy the separate authoritative-book resynchronization requirement.

Disconnect, refresh and expiry fence old-connection deliveries. Known exchange/market/global gaps invalidate pending deliveries for that scope. An unrelated exchange gap does not invalidate another exchange's pending print. Newly recorded prints after a gap may be observed, but no missing interval is filled or certified complete. This distinction preserves useful received facts without inventing continuous history. Raw topic revisions and transport drops remain uncalibrated because original raw transport frames are incomplete.

The existing `Flow` match identity/fact validation deduplicates REST and stream copies in either order. Conflicting facts fail. Source payloads are copied when queued. No extra actor metadata reveals hidden engine state, private order flow, unavailable aggressor direction or future receipts. Public-delivery counters are diagnostics only, not new features.

Focused tests cover receipt timing, no free history replay, zero added REST reads, model feature visibility, WAIT interruption, default behavior, duplicate ordering, disconnect/reconnect, exact expiry, payload immutability, scoped gap fencing, conflicting facts and complete-episode reconstruction/optimization. The integration fixture initially selected the legal stream-disconnect control through its old family11 bias; it was corrected to use a connected WAIT policy for this test. Production action support was not restricted to satisfy the fixture.

Active GPU020 and the queued GPU021 source remain frozen during development. Adoption requires a checked source/configuration handoff and new evaluations; old scores do not qualify the changed observation profile. This fills an API observation gap, not a demonstrated source of profit. Full requested history, calibrated fills/valuation, multi-day human-reward qualification and untouched independent testing remain incomplete. Original [SIG API documentation](https://sig.thesuper.market/api/v1/docs); this work relies on the pinned saved schema, not fresh live-schema verification.
