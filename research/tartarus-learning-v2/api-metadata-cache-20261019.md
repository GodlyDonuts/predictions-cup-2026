# Cache invariant API metadata, keep dynamic observations fresh

An actual recorded-world CPU profile of 2,300 entity rows found roughly 40% of cumulative observation-construction time inside the newly added public API metadata layer. The profile includes instrumentation overhead; its 11.919ms median is not the uninstrumented baseline.

The observation adapter now caches only its appended 31 metadata columns. Its exact context includes the ordered entity rows, declared exchange catalog, exchange-to-market mapping, ordered custom quote packet and issued cursor filters. Any context change rebuilds metadata. The cached matrix is immutable; each caller receives its own output matrix. Prices, full depth, cash, positions, debts, ages, local action history and action masks still come from the fresh parent observation on every call. No actor information, action family, API frequency or virtual time is added or removed.

The interleaved actual-data comparison runs the original function from checked source `741397cc2fb6d27c7beb9dc7625551a05c52c9dd` against the cached function on the same world. It changes the clock and ordered quote selection, alternates measurement order, and checks every contract/global/present tensor, entity and action mask. After eight warm-up pairs, medians over 72 pairs were 8.0975ms original and 6.20815ms cached: 1.3043 times faster **observation construction**, or about 23.3% less observation time. All 80 pairs were exact. This ran on CPU alongside the existing learner; there was no GPU diagnostic. It is not a whole-training, production or ROI measurement. [Exact benchmark](api-metadata-cache-benchmark-002.json).

The first benchmark harness incorrectly required an empty initial API budget even though this profile requests its initial realtime token. That failed check is retained and not credited. The corrected harness checks that observation calls add no admissions relative to their actual starting budgets.

The CPU suite passes 357 checks in 70.243 seconds, skipping four CUDA checks while the learner owns the device. Focused checks cover caller-mutation isolation, ordered duplicate packets, catalog/cursor invalidation, fresh delivered quotes and ages, accepted PPO and sealed episode reconstruction. GPU019 remains on its original frozen source; no running source or model was patched and no restart was requested for this optimization. It is available for a future checked training boundary, with a fresh capacity/source audit if adopted. No production or held-out financial state changed. Independently profitable ROI remains unproved.
