# October 21: production disk outage and recovery work

The candidate build exhausted the VPS filesystem. The original R66 worker stopped at15:10:13 UTC with `No space left on device`; systemd's15:11 restart also failed for lack of space. It restarted the same checked R66 binary as PID1010157/startTicks56518875 at15:12:14. At15:31 the worker was still restoring its original ledger. The15:08 progress file belongs to the previous process and is not evidence of resumed trading.

The first remediation removed reproducible compiler libraries, old test executables and linker products, after recording each exact path, inode, size, timestamp and SHA256. Sources, build commands, qualification logs, current dependencies, installed releases, checkpoints and all trading records were preserved. Free space rose to approximately3.95GB. The unchanged quota-removal candidate then linked successfully at15:26:42; it is **not deployed**. Its exact optimized binary SHA256 is `aa3b2b67890b0897f29073e1e4afc51bf007902818ffc11a36565b3361ee93ba6`.

That headroom is temporary: retained SDK account-queue generations occupy most of the production directory. `archive_cold_queue.py` adds a finite online archival path. It pins the existing worker's process creation, executable hash and account lease; takes a separate archival lease; admits only superseded generations older than one day; excludes the selected checkpoint/journal, its source journal and every file currently open by the owner; and rejects manifest regression or changed ownership. Each bounded archive is fsynced, fully decompressed and checked against every original SHA256 before originals are rechecked and unlinked. Archives retain the original bytes and an inventory for explicit later extraction. Current manifest, account state, STOP controls, bank and trading intents are not edited. The original offline archival path retains its original locking and exact-manifest requirements.

Eleven archival checks passed on the ARM64 VPS, including actual zstd round trips, current-file preservation, rotation during archival and owner loss before unlink. The initial read-only production preflight found30 eligible cold files totaling1,014,275,504bytes; the current and predecessor generations were excluded. The bounded production archival run and fresh restored-worker evidence will be recorded separately after execution. No new account client or trading authorization is created by archival.
