# Single-side admission before sizing: finite comparison

At source `bfd1e368`, native `quoteMode=microprice` already admits individual ordinary sides before sizing. With **the same book, fixed limits, zero fees, insideTicks/backoff zero, minimumSpreadTicks one and minimumEdge .001**, its scalar side test matches the runtime pairedSpread side filter: YES value is the integer-floored microprice; NO value is its exact complement; require value − limit − one-share fee ≥ .001. No model probability or fill-conditional return is established by that displayed-depth proxy.

This is not full strategy equivalence. Native pairedSpread additionally rejects the entire pair if its fee-inclusive spread is less than twice minimumEdge; microprice can retain one qualifying side in that situation. A nonzero-fee counterexample is tested. The actual zero-fee, one-tick-minimum spread makes that pair guard redundant for these snapshots, but not for arbitrary policies. Runtime uses a later original REST book, can return Unavailable, and exempts covered hedges/reviewed/package paths. Native microprice acts on its current admitted book and supports an optional minimumDepthImbalanceBps absent from pairedSpread. Neither removes the physical account/source/authority checks. Switching modes makes the pairedSpread-only runtime filter NotApplicable, so retaining a final native-to-physical side recheck would require a deliberate runtime change, not a mode flip alone.

The important difference is depth and reservation allocation. In [engine.rs](../../../moloch/native/src/engine.rs), desired-side admission is at 1090–1201; reconcile sizing is at 1326–1378. The first paired side (rank tie sorts NO before YES) is limited by **both** sides' displayed same-side top quantities and fee-inclusive pair unit funding. The second is limited to its mate quantity. Both get real native reservations before the physical side veto. Microprice removes the weak side first and uses the surviving side's own top depth and unit funding. The mate-quantity clamp remains if both sides qualify. This depth is quote-side displayed capacity; it is not evidence of future fills or a guarantee of liquidation at the purchase price. There is no simultaneous physical pair guarantee in ordinary dispatch.

## Recommendation

Align admission before sizing as a **prospective, bounded sizing experiment**, not an alpha upgrade. First shadow-record current-size versus independently sized eligible-side quantity/cash using each genuine original book and unchanged current policy. Preserve a final fresh same-criterion physical recheck. Predeclare a per-order principal/exposure bound rather than immediately taking the theoretical20.5×/117.1× quantity increases, and compare actual eligible opportunities, reservation-time, ACKs, partial fills, FIFO oldest-lot exits and net realized outcomes. Larger quoted size cannot create public demand, queue priority or favorable markout. The existing60s inventory policy/partial-fill timing remains a material risk.

The clean implementation is an explicitly reviewed native policy transition to existing microprice semantics (or a narrowly versioned pre-sizing side-admission mode) plus runtime physical recheck support. The native policy is bank-bound; changing controller JSON cannot silently change the replayed bank policy or relabel old quotes. Any engine/event implementation needs its own identity, old-prefix parity, transition evidence and production-owner rollout. Existing inherited SELL/hedge/review/package handling and funding/total/per-market/fresh-market caps must remain unchanged. No such transition, source mutation, trading action or profit claim is made here.
