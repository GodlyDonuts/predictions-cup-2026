**Current-quote experiment, recommended small source change:** add an optional
omitted-by-default typed proxy valuation descriptor and explicitly named source
adapter (with V1/V2 old bytes unchanged). It should:

1. Bind separately approved strategy/mapping digest, exact raw external cache

2. Recompute the frozen valuation using integer micro-units, selected side,
   discount, exceptional assumptions and margin; bind its canonical model hash

   the selected review's valuation to equal that recomputation.
3. Set acquisition validity to the minimum original external age deadline,
   review/source expiry, original SIG packet/book clocks and existing order/
   permit/activation deadlines. Recheck at the actual HTTP boundary. Never renew

4. Preserve real fresh full-depth SIG sizing, account/profile/funding checks,
   sole Transport limiter, immutable intent, unknown blocking, full owned tapes,
   terminal proof, principal cap and all existing owned-exit accounting.

The adapter reads the existing centralized external cache; it creates no Kalshi
or SIG client. Initial source review can use a fixed frozen packet, but a later
live acquisition must bind its actual original current packet. Do not inject
diagnostic JSON as a physical capability. Missing/stale/conflicting sources mean
unavailable, not a zero discount or an inferred price.

Reuse `Cohorts` instead of creating another portfolio ledger. Explicitly pinned
per-exchange principal caps exist today; a distinct aggregate experiment loss/
principal budget across several reviewed exchanges does **not** automatically
exist. For an initial bounded experiment use one reviewed flat contract or add a

Fast turnover also needs an honest exit objective. TerminalSettlement allows
holding until actual settlement and is not an intraday spread-convergence
strategy. DeadlineLiquidation requires a separate reviewed cash-at-deadline
model; a terminal probability or current external bid alone cannot supply it.
Dynamic repricing/revocation after entry would require an explicit approved
revision mechanism and source/holding horizon checks, not repeated new cohorts.

## Current update boundary

`worker.rs:1576–1581` reads Control and calls `Settings::load` only at startup;
the exact startup authority pin, immutable review hashes and verified sources
are then installed through `LoadedSettings::open_inner`. The run loop does not
reload Settings. Review files edited on disk are not newly approved/reloaded;
editing the held authority or Control fails their pinned validation. Runtime
review replacement is **not a supported hot-update interface**.

For a current-source experiment, the supported operational boundary is a root-
reviewed controlled restart with a new immutable review/allowlist/Control and
the same original bank/sidecar/owner/account queue. Existing DE/MA active
reviews/horizons remain untouched. A review-only restart with the identical
financial binary does not require inventing a new native engine identity or
financial migration. A typed-adapter binary change needs the normal checked
build/source and genuine existing deployment procedure; this assessment does
not execute either path.
