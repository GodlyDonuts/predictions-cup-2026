# Standalone one-pass journal restore V2

This prospective component does not change the existing journal-restore crate, pinned binary, runtime configurations or frozen model banks. It combines canonical record verification and raw source SHA-256 in the same opened-file pass. It returns the exact last body, original chain tail, prefix bytes, source digest, native file identity stamp and source-engine hash. Caller-supplied --expected-sha remains supported; COMPUTE obtains an independently checked first-pass digest without an earlier JavaScript hash pass. COMPUTE is not permission to trust a cache or roll back a previously bound prefix. Existing prefix/source/tail bindings must still be compared by the adapter.

Run build.ps1 -Test, then invoke target/release/baal-journal-stream-v2.exe --journal ABSOLUTE_FILE --end-byte BYTE_FRONTIER --expected-sha COMPUTE --out NEW_OUTPUT. --after-sequence, --after-hash and --suffix-out preserve the original suffix projection contract, with a freshly verified entire prefix. --worker accepts one compact JSON request per line containing journal, endByte and optional expectedSha; it responds sequentially and keeps one Rust process alive. Request lines are bounded to 64 KiB; journal records are bounded to 16 MiB. Only the last record is retained, not the journal history.

On Windows, the opened snapshot denies write/delete sharing for the scan; conflicting writers fail closed at open rather than accepting a concurrently altered prefix. Native Windows file ID, creation time, last-write stamp and size are checked on the same open handle after scanning and against a reopened path. Concurrent append, truncation, mutation and replacement fail closed; retry only after selecting a fresh explicit frontier. Unix uses device/inode and modification metadata. The collector adapter must also check its own before/after stamp and stop provenance immediately before restoring the append interface. This module verifies the original source chain and state bytes, not the economics of an arbitrary newly fabricated valid chain. The frozen reducer and wallet accounting checks remain required.

Benchmarks use a sealed copy of an actual existing original journal prefix in restricted runtime/offline-benchmarks storage. The temporary multi-GB snapshot is deleted after hash/state parity checks; only compact evidence is saved in data/journal-stream-v2-benchmark-20261005.json. No API traffic or competition orders are generated. Canonical-source parity and performance are correctness/engineering results, not profitability evidence.
