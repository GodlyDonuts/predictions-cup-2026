# Local paper dashboard

Next.js read-only dashboard at http://127.0.0.1:3000. The default Official account tab displays actual tournament positions, valuation P&L, the newest 100 fills, and open orders made by this account on the official platform. Independent scaled/conservative paper wallets remain separate tabs. It refreshes local statistics every five seconds; browser refreshes never contact the trading platform.

Run `pnpm install --frozen-lockfile`, `pnpm build`, then `pnpm start` from this directory, or use `Start-Dashboard.ps1` after installation/build. Keep the collector on port 8787 running. The launcher enables `official-sync.json` in the restricted runtime; restart an existing collector once to load this setting. The server binds only to the PC loopback interface. No API credential is required or read by this application. Its route fetches fixed loopback read endpoints and reads one fixed local performance projection, returning curated statistics. It has no trading controls.

Official account sync reuses existing position/open-order reads. One of the two historical read slots is replaced with a rotating GET for fills, daily P&L, or recent order history. It uses the collector's coordinated serialized pacing, persistent cooldown and account budget. The display is a sampled snapshot, not a realtime transaction feed: each section shows its last successful sync, errors preserve older snapshots, and extra fill pages are explicitly indicated. A fill's BUY/SELL action is joined from its matching order when known, otherwise shown as FILL; signed quantity determines YES/NO, never BUY/SELL. No raw account responses enter logs, the paper journal or GitHub. Account projections remain only in restricted LOCALAPPDATA. Tournament valuation values are separate from executable liquidation values.

The Bot position performance panel shows only reconciled quant-bot holdings. Run `Start-Performance.ps1` from the workspace to project observed full bid-depth and midpoint estimates from the existing capture without further API traffic. Missing or stale depth displays an unavailable estimate. The worker and route both enforce freshness; the route also checks that the report belongs to the current bot fill ledger. The browser ages the original report and quote timestamps every second, withholds stale price estimates during failed polling, and refreshes immediately on foreground/focus. Last-known cost remains explicitly labeled. Platform valuation marks remain separate.

When a valid local `entry-comparison-active.json` manifest names a frozen comparison cohort, Matched dip and Matched rebound tabs show its independent prospective paper wallets. The route reads only that restricted runtime subdirectory, checks bank/name identity, and returns curated wallet fields. Stale or failed worker reports retain historical accounting while withholding current market estimates. These two wallets use common execution assumptions; their hypothetical capital and fills are not additive, and public books may include account orders. See [comparison documentation](../live-paper/entry-comparison.md).

A valid `limit-entry-active.json` manifest adds Immediate dip and Price-capped dip tabs. Both apply the original historical-discount gates; the second policy can also wait for a one-tick-lower price that qualifies. Orders have a frozen 30-second lifetime. Only a later independent marketable quote supports a hypothetical fill, with one percent of displayed eligible depth and zero fees. The display distinguishes expiry without an in-window observation from expiry after observation with shares unfilled. These are independent policy wallets, not evidence that an actual resting order would have filled. Quotes age out in the browser after 20 seconds, even if polling stops.

Create a **new** named cohort with `Start-LimitEntry.ps1 -Name <new-cohort> -Initialize -KeepSession` from the workspace, then publish its exact `{schemaVersion:1,cohort,bankHash}` identity in the restricted runtime manifest. Reuse the same name without `-Initialize` to resume; never overwrite its bank or journal. The host verifies the complete source and derived journals on restart, freezes the imported code, and records actual first-consumption clocks. It makes no API requests. Inspect STOP provenance and ownership before restarting a failed worker.
