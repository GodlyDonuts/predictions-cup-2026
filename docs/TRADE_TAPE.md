# Public trade flow and collector replay

The single collector now captures documented official API v1 `/exchanges/{id}/trades` pages in the explicit Midterm Elections tournament. One anonymous-trade page replaces one existing history-read slot on alternate cycles. Account reconciliation, four depth slots, serialized completion pacing, the 20-read-per-minute allocation and persistent HTTP backoff remain in force. This adds no API client or background worker and enables no account writes.

The initial research scope is Tennessee 363/1052, West Virginia 297/986 and the New Hampshire pair 381/1070,382/1071. The host rotates the least recently observed exchange. It fixes each query's inclusive start/exclusive end before dispatch, retains opaque pagination across restart, and overlaps completed windows by one minute for reporting delays. Bootstrap looks back thirty minutes. The durable `anonymous-trades.jsonl` journal records sanitized public trades, receipt times, original response hashes, reporting checkpoints and pagination status. Corrupt journals, changing identities and cycling cursors are rejected. A STOP arriving during receipt prevents commitment.

Price is YES-normalized even when `side` says NO. Side denotes executed space, not the aggressor. Legacy trade IDs and engine sequences have different namespaces; deduplication includes exchange, source timestamp and executed space, with payload consistency checks. Null legacy prices stay null. A `coverage.complete` flag does not mean the first page contains all trades or that the reporting projection has caught up. Unfinished pagination and unknown projection lag remain visible. A minute of overlap cannot guarantee recovery from longer reporting delays. Anonymous prints never establish queue priority, counterfactual maker fills or profitability. Features derived from these pages first become available at the collector's recorded receipt time.

`book-publication-v2.mjs` preserves the original record format, validation and immutable state semantics while reusing already frozen objects and cached validated scope hashes. The runner uses this separate version; original frozen bank components remain intact. On the actual 12,967-row capture, the same 400-row prefix replay took 736.06 ms with the original and 105.92 ms with v2 (6.95 times faster). Full v2 replay took 3.67 seconds. These are reducer measurements, not order latency or trading returns. Live startup timing is separately published in `runtime.bookPublisher`.

Validation includes the unchanged twelve-case publisher contract executed against v2, byte-identical old/new journals and states, durable pagination recovery, overlap deduplication, source/time/scope rejection, STOP handling and shared read-only transport admission/backoff. Existing paper wallets keep their original banks and journals, zero added fees and observed spread/depth/latency assumptions.
